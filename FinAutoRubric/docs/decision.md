# 路径判定：B（缺少官方题目与 rubric）

- **判定日期：**2026-10-22
- **依据：**`docs/resources.md` §1–§2；原始探测见 `docs/resource_probe.json`
- **对应计划：**`plan.md` §4.3 路径 B

## 1. 判定

官方题目、逐题 rubric、评分代码与裁判提示词在本次可访问渠道中**均未定位到**，因此按计划走**路径 B**：

- 不使用 "FinAutoRubric 官方复现"、"官方评测"、"排行榜对比" 一类表述。
- 先用公开资源与自建夹具验证运行流程，实验使用独立名称与独立协议。
- 官方资源的缺失项逐条列出，向导师汇报或索取。

## 2. 这决定了什么

| 事项 | 路径 A 下会怎样 | 路径 B 下改为 |
|---|---|---|
| 题目 | 直接用官方 100 题 | 自建开发题／公开基准题，逐条标注来源与许可 |
| Rubric | 直接用官方逐题 rubric | 自建 rubric，并说明与论文口径的差异 |
| 裁判 | 用官方三裁判集成 | 自定裁判，先做规则裁判，再评估 LLM 裁判 |
| 成绩 | 可与论文表 3 比较 | 只能报告**自身前后对照**（B1 vs B2），不跨论文比较 |
| 声明 | 可称复现 | 只能称"受该论文启发的独立评测" |

## 3. 仍可借鉴的部分

- **失败分类 E1–E7**（plan §7.1）与论文的 rubric 结构（量化项／事实项／论证项）可以直接用于我们的分析。
- **信息截止时间** 这一设计是论文最有价值的约束，我们应原样保留：每题显式声明 `as_of`，并检查答案是否用了截止日之后的信息。
- **三裁判集成** 可以后置：第一轮先用规则裁判跑通，待有模型预算时再评估裁判一致性。

## 4. 需要导师决定或提供的资源

1. 是否存在内部访问渠道（题目＋rubric＋评分代码）？若有，请提供，我方立即改走路径 A。
2. 若无，是否接受以 BigFinanceBench／Finance Agent Benchmark v2 为题目来源，自建 rubric？
3. 模型预算：用哪个 API、月度上限多少、是否允许调用推理模型。

## 5. 重新判定条件

出现下列任一情况，重跑 `scripts/check_resources.py` 并更新本文件：

- 论文 v2 或 arXiv comments 给出代码链接；
- GitHub／Hugging Face 出现官方仓库或数据集；
- 导师提供内部资源。

在取得**题目、逐题 rubric、评分代码**三者之前，维持路径 B。
