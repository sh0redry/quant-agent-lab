# FinAutoRubric 论文解读

FinAutoRubric 的核心是“自动制定金融研究的评分标准”，同时附带一套金融研究 Agent 的测试题。它主要帮助判断研究报告是否正确、有证据、符合任务要求。

关于开源状态，我需要修正前面表述：目前不能把它当作已确认完整开源、下载即可运行的项目。 我找到论文第 3 页的明确脚注：“Code and data will be publicly released soon.” 本次也未定位到可确认的官方代码和数据入口。论文，第 3 页

## 1. 它解决什么问题？

金融研究很难只靠一个标准答案评分。例如：

> “分析一家公司的利润增长是否可持续。”

回答可能有不同结论，但需要检查数字、财务口径、来源、计算和论据。这里的 rubric 就是一张细化评分表。

下面是我举的示意例子，不是论文原题：

| 检查项 | 合格标准 |
| --- | --- |
| 数据是否正确 | 使用指定时期、指定口径的利润数据 |
| 计算是否正确 | 增长率与原始数字一致 |
| 是否考虑特殊项目 | 检查一次性收益、并购或会计调整 |
| 结论是否有依据 | 区分已经发生的事实与未来判断 |

如果每道新题、每个新日期都让专家重新编写这张表，成本很高。FinAutoRubric 尝试自动完成这部分工作。

## 2. 主要创新是什么？

可以把它理解为：专家规定原则，Agent 找依据并编制评分表，另一个 Agent 复核，代码执行硬性检查。

它将可复用的任务标准存入 Task Bank，再根据具体公司的问题、时期和信息截止时间生成评分细则。生成者需要查证预期答案，审核者重新核对来源和计算；规则违规或审核失败时转交人工。方法说明，论文第 2—5 页

因此，值得关注的创新是这几件事的结合：

- **标准复用：** 把通用研究要求与具体公司的事实分开。
- **证据支撑：** 评分表中的预期值也需要查证。
- **审核与约束：** 模型判断之外，再加入程序化检查。
- **按情境更新：** 同类任务可以针对新时期重新制定评分标准。

它并不是完全取消专家，而是希望让专家的原则反复发挥作用。

## 3. 现在进展到什么程度？

截至 2026 年 10 月 22 日，能确认的情况是：

| 层面 | 当前状态 |
| --- | --- |
| 论文 | arXiv 上可见 2026 年 9 月 28 日提交的 v1 预印本 |
| 方法验证 | 论文报告了三个金融基准上的比较及人工评价 |
| 配套 benchmark | 论文描述了 100 个问题，覆盖 78 类主要任务、八类资产 |
| 代码与数据 | 论文脚注写明即将发布；本次未找到可确认的官方完整入口 |

来源：arXiv 记录、论文。

所以，它目前适合当作值得研究的评价方法和候选基准。我们不应把“论文已有实验结果”理解为“外部团队已经能够独立复现”。

## 4. 我们能怎样利用它？

首先要区分两个研究对象：

| 路线 | 我们改进什么？ | 成功标准 |
| --- | --- | --- |
| 研究 Agent | 查找信息、理解财报、核验口径、形成结论 | 在固定且独立的规则下，研究质量提升 |
| 评价系统 | rubric 的生成、更新、验证和评分 | 更接近专家判断，且更可靠或成本更低 |

结合你现在的方向，我建议优先走第一条。 FinAutoRubric 可以提供评价思路；你们的贡献落在 Agent 的数据挖掘与感知能力上。

以下是我认为值得研究的几个问题，属于我们的候选方案，需要进一步核对相关研究与实验可行性。

### 方向 A：让 Agent 主动补齐缺失证据——最建议先做

例如，Agent 找到了利润增长的数据，却没有检查脚注中的一次性收益。

我们可以让它显式记录：

> 当前结论依赖什么证据？已经找到什么？还有什么未确认？

根据缺口继续搜索或计算。

实验比较普通检索 Agent 与证据补全 Agent，保持基础模型、工具和预算一致。重点看错误是否减少、证据是否更完整。

**关键区别：** 固定评分表只用于评价。不能把测试题的评分表或预期答案交给被测 Agent，否则它是在照答案完成任务。

### 方向 B：让 Agent 正确处理时间、版本和口径

研究问题可以是：

> 面对不同年份、重述版本和不同定义的数据，Agent 能否判断哪些数字可以比较？

可以构造包含旧文件、新披露和相互冲突数据的文档集合，检查 Agent 是否：

- 选择正确时期与版本；
- 识别币种、单位和财务定义；
- 发现冲突并解释处理方式；
- 在证据不足时避免强行给出结论。

这个方向更贴近金融数据的实际难点，也容易形成可检查的失败案例。

### 方向 C：研究“得分提高”是否真的意味着研究变好

这是偏评价方法的路线：

> Agent 是否可能通过增加措辞、引用或篇幅获得高分，却没有增加有效信息？

可以人为修改同一份回答：替换年份、删去关键证据、改变单位，或者加入无关但看似专业的段落，再检查评分变化。

如果评分系统对实质错误不敏感，或者奖励表面修饰，就需要改进规则或裁判。这里必须加入人工抽查，不能只让另一个 LLM 宣布评测可靠。

### 方向 D：把评价反馈用于训练或自我改进——放在后续

未来可以研究哪些反馈最有帮助：只有总分、指出缺失证据，还是指出具体口径错误。

但要先验证评分可靠性，再考虑将它用于 RL 或持续优化。同一套规则反复用于训练和最终测试，会让“研究能力提升”与“适应评分规则”难以区分。
