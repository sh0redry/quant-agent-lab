更新日期：2026-10-22
实验状态：**资源初查完成；协议升级到 v0.2；基线仍未开始**（无真实模型调用）

## 1. 结论

官方题目、逐题 rubric 与评分代码**在本次可访问渠道中未定位到**（论文 p.3 脚注 "will be publicly released soon"；GitHub 仓库搜索 0 命中，HF 无对应数据集）。因此按计划走**路径 B**：独立名称、自定协议、不与论文成绩比较。

离线链路已补充消息关联、重试与证据清单，并修复复核发现的工具超时、数字误判、截止日暴露漏报和 CLI 空题集问题。**真实基线仍需确定正式题目与独立评价集、模型和费用预算，并验证真实 API 多轮调用。**规则裁判只做保守的语法检查，尚不能可靠评估自然语言论证、财务期间指代或单位换算。

**这些分数没有研究含义**：题目与答案都是合成夹具，只证明评分能区分正确项与错误项。

## 4. 关键发现

1. **最大的风险仍是资源，不是工程。** 没有官方题目与 rubric，任何"复现 FinAutoRubric"的表述都不成立。
2. **协议与实现的偏差必须靠测试固定，而不是靠文档声明。** 上一版声称重试上限 1 次，实际恒为 0；这次用三个测试把它钉住了。
3. **"只看答案"与"看完整 trace"是两种测量，不是严格程度差异。** 已从协议里删掉"更严格"的说法。
4. **截止日干扰项要显式登记。** fc-02 故意包含截止日后的新闻稿；`cutoff_compliance` 记录读取及搜索引起的信息暴露，不等于判定最终答案使用了该信息。

## 5. 限制与下一步

- **当前限制：**无模型 API（也无预算）；未做真实调用；未做失败分析与基线；夹具题不能衡量 Agent 能力。
- **下一步：**确定题目来源与许可 → 冻结开发集、独立评价集与 rubric → 确定模型和预算 → 小预算真实协议验证 → B1 基线 → 按 E1–E7 做失败分析。
- **需要导师决定或提供：**① 是否有官方资源内部访问渠道；② 若无，是否接受公开基准＋自建 rubric；③ 模型与预算（哪个 API、上限、是否允许推理模型）。
