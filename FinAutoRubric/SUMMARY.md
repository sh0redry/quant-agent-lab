# FinAutoRubric 实验结论

更新日期：2026-10-22
实验状态：**资源核验完成；基线未开始**（第一轮仅做资源与协议核验，并离线验证评测链路）

## 1. 结论

官方题目、逐题 rubric 与评分代码**目前都拿不到**。论文第 3 页脚注写明 "Code and data will be publicly released soon"，同日探测 GitHub 仓库搜索 `total_count = 0`、Hugging Face 无对应数据集或模型，因此按计划走**路径 B**：使用独立名称与自定协议，不宣称官方复现，也不与论文表 3 的成绩比较。

在这一前提下，我们已把"读证据 → 计算 → 提交 → 按 rubric 评分 → 留痕"的链路用离线 mock 跑通，下一步的真实模型基线不再受工程问题阻塞。

## 2. 实际完成内容

- **资源核验：**九类资源逐项定性，见 [`docs/resources.md`](docs/resources.md) 与可复现探测 [`docs/resource_probe.json`](docs/resource_probe.json)；路径判定见 [`docs/decision.md`](docs/decision.md)。
- **协议冻结：**v0，明确区分"官方／未知／自定"，见 [`docs/protocol.md`](docs/protocol.md) 与 [`configs/protocol.yaml`](configs/protocol.yaml)。
- **工程链路：**`src/agent/`（provider 抽象、四工具、带预算的循环）＋ `src/eval/`（rubric 校验、规则裁判、run 编排）；16 个单元测试通过。
- **离线运行：**3 道**合成夹具题**（`data/fixtures/README.md` 已注明虚构），产出 `runs/<run_id>/` 下的 trace、score、config。
- **模型与 Agent：**mock provider（脚本化，确定性）；未调用任何真实模型，费用 0。
- **开发题／独立评价题：**0／0。夹具题只验证链路，不进入任何成绩。

## 4. 关键发现

1. **最大的风险不是工程，而是资源。** 没有官方题目与 rubric，任何"我们复现了 FinAutoRubric"的表述都不成立；必须先向导师确认是否有内部访问渠道。
2. **论文有三处方法可以直接借鉴：**信息截止时间（每题固定 cutoff）、rubric 的量化／事实／论证结构、三裁判集成。我们已在协议中保留前两项。
3. **裁判可见范围是一个必须显式记录的差异：**论文的裁判看完整 trace，我们 v0 只看最终答案。这不是简化，而是不同的测量，报告中必须写明。
4. **离线 mock 暴露了一个真实的设计点：**"没有 `submit` 就不算完成"这条规则必须由代码强制，否则文本回答会被误当成提交；循环里已按此实现并加了测试。

## 5. 限制与下一步

- **当前限制：**无官方资源；无模型 API（也无预算）；夹具题不能衡量 Agent 能力；尚未做任何失败分析。
- **下一步（需资源）：**确定题目来源（BigFinanceBench 或 Finance Agent Benchmark v2）→ 冻结 10 题开发集 → 接真实模型跑 B1 基线 → 做 E1–E7 失败分析。
- **需要导师决定或提供：**
  1. 是否有官方题目／rubric／评分代码的内部访问渠道；
  2. 若无，是否接受以公开基准为题、自建 rubric；
  3. 模型与预算（用哪个 API、上限多少、是否允许推理模型）。
